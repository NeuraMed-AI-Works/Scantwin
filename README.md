> ## ⚠️ Research & educational prototype
> ScanTwin uses simplified image-acquisition and exposure models and is **not intended for clinical diagnosis,
> patient-specific dosimetry, or scanner/protocol prescription.** It reports *relative exposure proxies* and
> *normalized acquisition costs*, never dose in mSv/Gy, and it performs **no disease classification**.
> Use only public, de-identified, licensed images. ScanTwin ships no patient data and downloads nothing automatically.

## What it does
A closed loop - **ground truth ➔ acquisition ➔ measurement ➔ noise ➔ reconstruction ➔ quality assessment ➔ optimizer** - that is
modality-aware. Pick a modality in the sidebar (**CT, X-ray, MRI, Ultrasound, Other**) and the whole app (protocol controls, labels,
live view, optimizer, experiments, learning) switches to that modality's simplified physics.

| Modality | Simplified model | Cost proxy (reference = 1.0) |
|---|---|---|
| CT | parallel-beam Radon, Beer-Lambert, Poisson, FBP/SART | photon budget + views |
| X-ray | line-integral map, Poisson, inverse log, post-filter | photon budget |
| MRI | k-space, centre-weighted undersampling, complex noise 1/√NEX, zero-filled recon | scan-time proxy (R, NEX) |
| Ultrasound | speckle statistics, frame compounding, log compression | frame count |
| Other | generic CT-style **proxy** | as CT |

Every modality has a "Model scope" box in the app and in `docs/assumptions.md` / `docs/limitations.md`.

## Install and run locally
**Windows**
```
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```
(`run_app.bat` does the last step.)

**macOS / Linux**
```
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

**Run the tests**
```
pip install -r requirements-dev.txt
pytest
```
`nibabel` (NIfTI) and `pydicom` (DICOM) are optional readers; the app tells you if one is missing.

## The nine tabs
1. **Train & Analyze** - quick-start dataset sources, upload your images, *Train from my images* (or the built-in synthetic demo set), then upload test images and get one result card per image, a CSV and an optional report.
2. **Digital Twin** - one acquisition end to end with metric cards.
3. **Live Acquisition** - real-time reveal: CT views (golden-angle order), MRI lines (centre first), ultrasound frames accumulating, X-ray exposure ramp, slice stream. The final live frame equals the batch result.
4. **Compare** - reference vs your protocol.
5. **Reconstruction** - modality-specific reconstruction variants.
6. **Quality vs Cost** - sweeps of the primary cost parameter.
7. **Optimizer** - Optuna TPE search; reports the cheapest *feasible* protocol or "No feasible protocol found within the current search space."
8. **Experiments** - sweeps saved to `results/<modality>/` (timestamped, never overwritten).
9. **Methodology** - equations, assumptions, limitations.

## Learning from your own images
For each image the digital twin simulates a small protocol grid; a RandomForest learns SSIM/PSNR from image descriptors + protocol parameters.
It is evaluated with image-grouped cross-validation against a mean baseline, with a novelty check and a modality-mismatch warning.
One model per modality (>= 3 images, 8+ recommended); fewer images fall back to a pooled model, which is flagged.
Models are saved as `models/protocol_model_<modality>.joblib`.
**A recommendation is shown only if a twin simulation confirms it with the single authoritative `is_protocol_feasible`.**
> ⚠️ `.joblib` files are pickles: load only model files you created yourself.

## Data
See `data/README.md`: MedMNIST+ (Zenodo `_64` files) and the Medical Segmentation Decathlon (MRI tasks: BrainTumour, Heart, Hippocampus, Prostate) are listed as sources; you download them yourself.

## Honest status
* Noise levels and default criteria are arbitrary starting values, not calibrated to any device.
* `docs/validation_report.md` is generated by `python scripts/generate_validation_report.py` from real runs (synthetic phantom); no number in it is typed by hand.

## Project layout
```
app.py                 thin orchestrator (9 tabs)
ui/                    tab_<name>.py modules with render(ctx), sidebar, shared helpers
modalities/            Modality interface + ct, xray, mri, ultrasound
digital_twin/          TwinState, DigitalTwin, is_protocol_feasible
simulation/ reconstruction/ metrics/ optimization/ learning/ experiments/
docs/ tests/ models/ results/ data/
```

## Deploy your own copy (Streamlit Community Cloud)
1. Fork this repository.
2. Go to <https://share.streamlit.io>, sign in with GitHub and choose **Create app**.
3. Select your fork, branch `main`, main file `app.py`; under *Advanced settings* choose Python 3.11.
4. Click **Deploy**. Later pushes to `main` redeploy automatically.

Free-tier notes: the file system is temporary (saved models and experiment results disappear on reboot) and memory/CPU are limited, so very large uploads or long optimizer runs may be slow.
